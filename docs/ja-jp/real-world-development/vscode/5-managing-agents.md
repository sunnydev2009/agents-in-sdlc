GitHub Copilot をエージェントモードで使うと、コードベースを調査し、変更を提案し、ファイルを編集して、コマンドを実行します。VS Code の Copilot Chat では、ツール呼び出しやファイル編集がリアルタイムで表示されます。差分をインラインでレビューし、個々の変更を採用または取り消し、フォローアッププロンプトで作業を調整または拡張できます。エディターを離れる必要はありません。

この演習では、次の内容を学習します。

- アクセシビリティエージェントの作業をリアルタイムで監視します。
- 提案されたファイル編集をレビューして採用します。
- セッションの途中でエージェントに指示し、ハイコントラストモードと並んでライトモードを追加します。

## シナリオ

[演習 4][previous-lesson]で使ったアクセシビリティカスタムエージェントが、ハイコントラストモードを実装しています。作業中、デザインチームから追加の依頼がありました。既定のテーマが暗すぎると感じる人向けに、ライトモードも切り替えられるようにします。新しい会話を始めるのではなく、既存のセッションに指示して作業を拡張します。

## Copilot の進捗を監視する

Copilot Chat ビューでは、エージェントが調べるファイル、実行するコマンド、提案する編集など、各ステップを確認できます。ファイル編集は差分と **Keep** / **Undo** の操作とともにチャット内に表示されます。

1. 演習 4 で使った Copilot Chat ビューに戻ります。
2. エージェントの作業中はチャットをスクロールし、ツール呼び出しを確認します。ファイルの読み取りや編集、実行を求めるターミナルコマンドが表示されます。
3. エージェントがファイルの編集を提案すると、差分がインラインで表示されます。
   - **Keep** を選択して変更を採用します。
   - **Undo** を選択して変更を取り消し、もう一度作業するようエージェントに依頼します。
4. チャット上部の **Files changed** を開き、このセッションで変更されたファイル全体を確認することもできます。

> [!NOTE]
> ターミナルコマンドの実行などでツール呼び出しの許可を求められると、エージェントは一時停止して **Allow** を表示します。内容を確認し、許可してよいコマンドだけを承認してください。

5. エージェントがハイコントラストモードを実装し終えるまで待ちます。最後に、変更内容をまとめたメッセージが表示されます。

## ライトモードを追加するようエージェントに指示する

ハイコントラストモードができたら、同じ会話でライトモードの切り替えを追加します。同じチャットセッションを続けるため、エージェントは前の作業のコンテキストを保持しています。変更したコンポーネント、スタイルの方針、local storage を使った設定の保存方法などが含まれます。

1. Copilot Chat の入力欄に次のフォローアッププロンプトを送信します。

    ```plaintext
    Nice work! Now add a light-mode toggle alongside the high-contrast toggle. Light mode should follow the same pattern — persist via local storage and be accessible from the same area of the UI. The user should be able to enable high-contrast and light mode independently.
    ```

2. エージェントは既存の変更を調べ、ライトモードの追加を提案します。
3. 変更が表示されたら、ハイコントラストの場合と同様にレビューし、各差分で **Keep** または **Undo** を選択します。
4. エージェントが希望しない方針 (たとえば、切り替え UI を意図しない方法でリファクタリングする場合) に進んだら、チャット入力欄の横にある **Stop** ボタンで停止し、明確なフォローアップメッセージを送信します。

> [!TIP]
> 進行中のセッションに指示を出すほうが、最初からやり直すより短時間で済みます。フォローアッププロンプトで調整を依頼できます (「CSS を簡潔にして、セレクターの重複ではなく CSS 変数を使う」)、方針を修正できます (「3つ目の切り替えを追加せず、既存の設定パネルにライトモードを組み込む」)、作業範囲を広げることもできます (「両方の切り替えにキーボードショートカットも追加する」)。

## 変更されたファイルをレビューする

作業をコミットする前に、エージェントが変更したすべての内容を確認します。

1. VS Code で **Source Control** ビューを開きます。
2. 変更されたファイルの一覧を確認します。Astro コンポーネント、スタイル、関連テストなどが更新されています。
3. 変更されたファイルをいくつか開き、差分を確認します。カスタムエージェントのアクセシビリティ手法 (Accessible Rich Internet Applications (ARIA) 属性、キーボード操作、セマンティック HTML、local storage による設定の保存) が反映されていることを確認します。
4. 問題がなければ、Source Control パネルから変更をステージングしてコミットします。次のレッスンで公開します。

## まとめと次のステップ

Copilot Chat のエージェントモードで進行中のセッションを監視して案内しました。ファイル編集を確認して採用または取り消し、コンテキストを保ったままフォローアッププロンプトで作業を拡張しました。

このレッスンでは、次の内容を確認しました。

- エージェントの作業をリアルタイムで監視する。
- 個々のファイル編集を採用または取り消す。
- フォローアッププロンプトでセッションの途中から方向を調整する。

[次のレッスン][next-lesson]では、アクセシビリティの作業を pull request として公開し、このラボでローカルのカスタムエージェントが作成した変更をレビューします。
